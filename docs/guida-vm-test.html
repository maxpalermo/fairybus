Test Fairy Bus su macchina virtuale

Guida alla creazione di un server minimale con GNOME Boxes, installazione di Docker e deploy del pacchetto fairybus-install-1.0.0.zip

1. Creazione della VM in GNOME Boxes

  1. Apri GNOME Boxes → + → Crea macchina virtuale.
  2. Nell'elenco dei sistemi operativi scorri in fondo e scegli File immagine del sistema operativo → seleziona la ISO Debian scaricata (riquadro sotto).
    Evita il download automatico dall'elenco: il registry di Boxes punta a una point-release archiviata e fallisce con "Scaricamento non riuscito".
Download manuale della ISO (già eseguito su questa macchina): 
# scarica la netinst Debian corrente (~756 MB)
mkdir -p ~/iso
cd ~/iso
curl -fSL -o debian-13.7.0-amd64-netinst.iso \
  https://cdimage.debian.org/debian-cd/current/amd64/iso-cd/debian-13.7.0-amd64-netinst.iso
La ISO si trova già in /home/massimiliano/iso/debian-13.7.0-amd64-netinst.iso.
Per versioni future: indice su cdimage.debian.org/debian-cd/current/amd64/iso-cd/ (scegli il debian-*-amd64-netinst.iso più recente).
  1. Alla schermata Personalizza imposta le risorse:
    Risorsa Valore Note
    CPU 2 core 4 consigliati se disponibili
    RAM 6 GB minimo 4 GB: MariaDB usa 2 GB di buffer pool + PHP 2 GB di memory limit
    Disco 25 GB le 3 immagini Docker occupano ~1,7 GB decompressi + database
  2. Conferma e avvia: l'installer Debian parte nella finestra della VM.

2. Installazione di Debian

  1. Scegli Install (grafica non necessaria) e procedi: lingua, tastiera, hostname (es. fbtest).
  2. Imposta password root e crea un utente normale (es. fb).
  3. Partizionamento: Guidato — usa l'intero disco, tutto in una partizione.
  4. Alla schermata Selezione software (tasksel):
    • togli la spunta da Debian desktop environment
    • spunta SSH server ← fondamentale per il passo 6
    • tieni standard system utilities
  5. Installa GRUB sul disco virtuale, riavvia e togli la ISO quando richiesto.
Risultato: un server minimale, senza interfaccia grafica, con SSH attivo — identico a un VPS reale.

2.1 Problemi comuni dopo l'installazione

Comandi base mancanti (sudo, curl, unzip)

L'installazione minimale non include sudo e curl. Si installano da root:

su -                                      # password ROOT, non quella utente
apt update
apt install -y curl sudo unzip ca-certificates
usermod -aG sudo NOMEUTENTE               # es. fb
exit
# poi riloggati o esegui: newgrp sudo

Password di root dimenticata

Attenzione: l'installer chiede due password — root e utente. Se su - fallisce con Autenticazione non riuscita, riprova con la password di root. Se proprio non la ricordi:

  1. Riavvia la VM → al menu GRUB premi e sulla voce Debian
  2. Trova la riga linux /boot/vmlinuz-... root=UUID=... e aggiungi in fondo: init=/bin/bash
  3. Ctrl+X → shell root diretta, poi: 
    mount -o remount,rw /
passwd root          # nuova password
exec /sbin/init      # continua il boot

Voce sintetizzata che parla a ogni azione

Causa: al menu di boot non è stato premuto un tasto entro il countdown → l'installer è partito in modalità accessibilità e il sistema installato ha espeakup attivo.

sudo systemctl disable --now espeakup     # ferma e disabilita
# oppure rimozione completa:
sudo apt purge -y espeakup
# se parla anche prima del login:
sudo modprobe -r speakup_soft
echo "blacklist speakup_soft" | sudo tee /etc/modprobe.d/no-speakup.conf

Se reinstalli: al menu di boot premi subito un tasto per fermare il countdown, poi scegli Install.

3. Installazione di Docker nella VM

Login nella console della VM (o via SSH), poi:

curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER

Ricollegati (logout/login) e verifica:

docker --version          # Docker 2x.x
docker compose version    # plugin compose v2.x <-- richiesto da install.sh

4. Trasferire il pacchetto nella VM

Sull'host (questa macchina), nella cartella del progetto:

cd /home/massimiliano/docker/fairybus/mysql
python3 -m http.server 8000

Nella VM:

wget http://10.0.2.2:8000/fairybus-install-1.0.0.zip
unzip fairybus-install-1.0.0.zip
cd fairybus-install
10.0.2.2 è l'indirizzo con cui la VM vede sempre l'host sulla rete slirp di Boxes (NAT user-mode). Funziona in uscita dalla VM; non è possibile raggiungere la VM dall'host via IP — per quello serve il port-forward del passo 6.

5. Installazione dell'app

./install.sh

L'installer chiede in sequenza (premere Invio per i default):

Prompt Default Note per il test
Porta HTTP 8080 lascia 8080
URL pubblico http://localhost:8080/ in VM metti http://localhost:8890/ — la porta che userai nel browser dell'host tramite il forward
Suffisso istanza vuoto vuoto = fairybus-app/-db/-pma; -demo per una seconda istanza
Email admin admin@fairybus.local utenza di login
Password admin generata annota quella stampata a fine install

Al termine lo script mostra URL e credenziali.

6. Aprire l'app dal browser dell'host

Boxes usa rete slirp (NAT user-mode): la VM ha IP interno 10.0.2.15 raggiungibile solo in uscita — l'host non può aprire connessioni verso la VM. Il tunnel ssh -L non funziona: serve un hostfwd aggiunto a caldo sul netdev QEMU.

# sull'host, a VM accesa (comandi già pronti in fb-vm-forward.sh):
export LIBVIRT_DEFAULT_URI=qemu:///session
virsh qemu-monitor-command debian13 --hmp 'hostfwd_add hostnet0 tcp::8890-:8080'
virsh qemu-monitor-command debian13 --hmp 'hostfwd_add hostnet0 tcp::2222-:22'

Poi dall'host: ssh -p 2222 <utente>@localhost per la shell, e nel browser:

Servizio URL
App http://localhost:8890/login
phpMyAdmin http://localhost:8890/pma/ (o voce PMA nel menu, solo admin)
Note sul forward:
  • Connection refused su ssh -p 2222: i forward si azzerano a ogni riavvio/spegnimento della VM → rilancia ./fb-vm-forward.sh
  • Non persistente: va rilanciato a ogni avvio della VM → ./fb-vm-forward.sh
  • Porta host: qui 8890 perché la 8080 dell'host era occupata da un altro container — scegline una libera
  • URI: qemu:///session — i domini di Boxes non si vedono con virsh di sistema
Verifica finale: login con l'email/password dell'installazione → dashboard vuota (database factory), menu laterale con PMA in fondo, phpMyAdmin raggiungibile a /pma/.

7. Importare un backup del database (ripristino)

Per caricare nell'app un database esistente si usa la funzione Backup/Ripristina di Impostazioni: l'app legge gli archivi dalla cartella writable/backups del container, che è un named volume Docker — il file va copiato con docker cp, non nel filesystem della VM.

Formato richiesto

  • Il nome del file deve seguire il pattern fb-backup-AAAAMMGG-OOmmSS.zip (es. fb-backup-20261017-150604.zip)
  • Lo ZIP deve contenere un file backup.sql nella radice — non un .sql sciolto né altri nomi

Se hai già uno ZIP prodotto dall'app

Un fb-backup-*.zip scaricato da un'altra installazione è già pronto:

# nella VM, dalla cartella dove si trova lo zip
docker cp fb-backup-20261017-150604.zip fairybus-app:/var/www/html/writable/backups/
docker compose exec app chown www-data:www-data /var/www/html/writable/backups/fb-backup-20261017-150604.zip

Se hai un dump .sql esterno (mysqldump, phpMyAdmin…)

Va incapsulato nel formato atteso dall'app:

mv mio-dump.sql backup.sql
zip fb-backup-20261017-150604.zip backup.sql
docker cp fb-backup-20261017-150604.zip fairybus-app:/var/www/html/writable/backups/
docker compose exec app chown www-data:www-data /var/www/html/writable/backups/fb-backup-20261017-150604.zip

Verifica che l'app lo veda:

docker compose exec app ls -l /var/www/html/writable/backups/

Ripristino

  1. Apri http://localhost:8890/admin/settings → tab Backup
  2. Il file copiato compare in elenco → pulsante Ripristina
Attenzione:
  • Il ripristino esegue DROP TABLE su tutte le tabelle — sostituisce completamente i dati attuali
  • Se hai installato con suffisso (es. -demo), il container è fairybus-app-demo — controlla con docker ps --format '{{.Names}}'
  • Il dump viene eseguito statement-per-statement: dump creati dall'app o da mysqldump funzionano; formati esotici possono fallire a metà — in tal caso importa via phpMyAdmin (/pma/) o docker exec fairybus-db mariadb …

8. Aggiornare l'app (patch e release)

Il codice dell'app è montato dalla cartella ./app-src (bind mount su /var/www/html), popolata dall'immagine al primo avvio. Gli aggiornamenti si applicano con ./update.sh senza reinstallare e senza toccare dati (DB, upload, sessioni).

Pacchetto Quando usarlo Comando
fairybus-patch-X.Y.Z.zip Fix rapidi: contiene solo i file modificati (KB/MB) ./update.sh fairybus-patch-1.0.1.zip
fairybus-app-X.Y.Z.tar.gz Release complete: nuova immagine Docker (~200 MB) ./update.sh fairybus-app-1.0.1.tar.gz

In entrambi i casi update.sh esegue automaticamente: estrazione/sincronizzazione del codice in app-src, migrazioni DB (spark migrate), pulizia cache Twig e riavvio del container — necessario perché l'opcache PHP non rivalida i file.

Attenzione:
  • Eventuali modifiche manuali ai file in app-src vengono sovrascritte dagli aggiornamenti
  • Le patch zip devono contenere i file con path relativi alla radice del progetto (es. app/Config/App.php, public/assets/…) — li genera lo script make-patch.sh in ambiente di sviluppo
  • Per copiare il pacchetto nella VM usa lo stesso canale del paragrafo 4 (http://10.0.2.2:8000/…) o scp -P 2222

9. Note e risoluzione problemi

  • Seconda istanza di test: scompatta lo zip in un'altra cartella, riesegui install.sh con porta diversa (es. 8081) e suffisso -demo.
  • Reinstallare da zero: docker compose down -v && rm -f .env app.env && ./install.sh (cancella database e upload).
  • Log: docker compose logs -f app oppure db/pma.
  • phpMyAdmin login: root + MYSQL_ROOT_PASSWORD dal file .env della cartella di installazione.
  • RAM insufficiente: se la VM ha solo 4 GB e va in swap, riduci innodb_buffer_pool_size in my.cnf a 512M e docker compose up -d.
  • Pacchetto offline: tutte e 3 le immagini Docker sono nel file — la VM non ha bisogno di scaricare nulla da Docker Hub.
  • ssh -p 2222 → "Connection refused": la VM è stata riavviata/spenta e i port-forward slirp sono andati persi → riesegui ./fb-vm-forward.sh. Se persiste: verifica che la VM sia accesa (virsh -c qemu:///session domstate debian13) e che sshd sia installato (systemctl status ssh nella console).
  • La pagina si apre ma senza grafica (no CSS): l'URL pubblico inserito nell'installer non corrisponde a quello digitato nel browser — l'app genera i link degli asset con app.baseURL (es. localhost:8080 invece di localhost:8890). Fix dalla cartella di installazione, nella VM: 
    sed -i 's|^app\.baseURL = .*|app.baseURL = http://localhost:8890/|' app.env
docker compose restart app
docker compose exec app rm -rf /var/www/html/writable/cache/*
    poi ricarica con Ctrl+F5. Regola: l'URL pubblico va sempre scritto come appare nella barra del browser.
